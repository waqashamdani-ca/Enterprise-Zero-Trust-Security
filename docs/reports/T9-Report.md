#### Proposed writing and layout standard

The main manual should help a learner perform and check an approved lab action. Start with the business access problem and how to use the five private working records. Keep the five phase names and a compact linked contents list. Use short step titles and four repeated labels: **WHERE** (computer/application/menu), **DO** (normally 3-7 numbered actions), **CHECK** (one observable expected result) and **RECORD** (exact existing worksheet/section). Explain each essential term once. Give an exact menu/field/value or a precise technical reference; never substitute an instruction such as "configure correctly". Split a complex operation into meaningful procedures rather than hide multiple changes in one sentence.

Keep a short prerequisite/safety note only where needed: named stage/asset/scope approval, correct target, isolation, credential custody and recovery before a write. Retain exact technical actions, release/backend conditions, positive/negative controls, second observations, verification and recovery. Use a one-line stop/recovery instruction for the common failure; link advanced diagnosis. Record actual observations only, retain failures and leave missing tests NOT TESTED. Owner UAT remains a separate decision. Keep task IDs, procurement/progress details, repeated warnings and background theory out of the learner-facing text.

Proposed PDF: US Letter portrait, consistent 0.75-inch margins, embedded package fonts, 10.5-11 pt body with approximately 14 pt leading, compact navy headings and dark gray body text. Use 2-4 columns for simple comparisons, modest pale-gray header fills, complete rows, visible numbered actions and distinct monospace technical values/code. Keep an action and any attached command/check together; move an entire short procedure only when necessary, without full-page divider sheets. Use a small running title, page numbers, source-derived version, clickable internal/external links and bookmarks. Add no cover or contents-only page to the small sample. The full guide's approximate 12-18-page target is a design budget, not an acceptance metric or reason to omit safety/actions.

Phase 1 starts with verification of prepared Dell/Proxmox, physical HP/OPNsense, TP-Link switch and Beryl AX, three workloads (DC1/WIN1/APP1) and Management/Corporate/Restricted. No firewall VM, four-VM installation exercise or mandatory six-VLAN plan. Planned guest allocations remain 6 vCPU / 16 GiB RAM / 160 GiB disks; the separate host/storage reserves and 320 GiB provisional ledger remain architecture-owned, not measured facts. Read-only inspection cannot establish a complete FWT-01/FWT-02 pass.
